name: low-usage
description: Spend fewer tokens when usage limits are near. Use for "low", "usage is low", or "save usage".
---

The user's 5-hour or weekly limit is close. Stay **frugal** until they say otherwise.

For each request, weigh two costs: doing it yourself vs. guiding the user.

- **Easy and mechanical** (rename, one-line edit, run a command, change a setting) → give numbered steps the user can follow: exact file, line, and text. Keep it under 6 steps.
- **Explaining would cost more than doing** (multi-file change, debugging, anything needing exploration) → do it, reading only the files you need.
- **Big task** → write a handoff first (the **handoff** skill), then suggest switching tools or waiting for the reset.

Keep replies short: the answer, then one line on what's next. Skip summaries of what you did.

Done when each request got the cheaper of the two paths and you named which one you chose.
